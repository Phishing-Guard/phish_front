프론트엔드 구현 요약
---
## 1. 전체 UI 구조 설계 및 페이지 구성
프론트는 총 3개의 주요 페이지로 구성

### Start 페이지 (index.html)
전체 서비스 소개 슬라이더 구현

이미지/문구가 자동으로 전환되는 캐러셀(slider) 개발

안전 문자 판별 페이지로 이동하는 대형 링크박스 UI 구성

배경, 버튼, 안내문 등 전체 홈 화면 디자인 구성


### Info 페이지 (info.html)
문자 복사 → 붙여넣기 과정 안내 UI 제작

단계별 이미지(1단계~3단계)와 설명 박스 레이아웃 구현

“문자 위험도 확인하러 가기” 버튼으로 테스트 페이지 이동


### Test 페이지 (test.html)
사용자 입력 Textarea UI

분석 결과를 시각적으로 보여주는 Output 영역 구성

상태별 배경 색상 변화(안전 / 주의 / 피싱)

분석 결과 보기 → 다시하기 버튼 상태 자동 변경

---
## 2. UI/UX 디테일 구현 요소
### 슬라이더(캐러셀) 직접 구현

(자동 슬라이드 / 화살표 클릭 이동 / 하단 DOT 인디케이터 포함)

setInterval() 기반 자동 전환 기능

좌우 화살표 클릭 시 슬라이드 이동

Dot 클릭 시 특정 페이지로 이동

transform X축 이동으로 부드러운 애니메이션 처리

슬라이더 초기화, 재시작 로직 개발


### 로딩 UI 애니메이션 구현

문자 분석 버튼 클릭 시, 배경 색상 변경, “문자를 분석하는 중입니다” 텍스트 표시

3개의 점이 순차적으로 깜빡이는 애니메이션 (@keyframes blink) 적용

textarea 입력 비활성화 처리

사용자에게 실제 분석 중임을 직관적으로 보여주는 UX 효과 제작.


### 결과 UI 동적 렌더링

백엔드 분석 결과에 따라 화면이 성공적으로 업데이트되도록 개발

분석 결과 항목은 안전, 주의, 피싱 세가지로 각 타입별로 다른 색상, 다른 UI 구성 적용


#### 안전

깔끔한 한 줄 메시지

중앙 정렬된 큰 텍스트 표시


#### 주의/피싱

분석 메시지, 감지된 위험요소 리스트, 해결방법 리스트 표시

<li> 리스트 자동 생성
  
박스 레이아웃(fancy-row, short-box, long-box)으로 정돈된 UI

## 3. 백엔드 API 연동 (fetch)

Test 페이지에서 사용자가 입력한 내용은 API로 전달됨.

fetch() 로 POST 요청 전송

에러 처리 (서버 오류, 응답 오류 포함)

성공 시 결과 JSON 파싱하여 UI 렌더링

실패 시 alert 및 화면 초기화 처리

---
## 4. 상태 초기화 / 버튼 기능 제어

“분석 결과 보기” → 분석 완료 후 “다시하기”로 변경

다시하기 클릭 시 전체 화면 초기화

textarea disable/enable 제어

summary 박스 색상 초기화

## 5. 세밀한 CSS UI 디자인 담당

#### 사용자 경험을 고려한 CSS 스타일링 전체 담당

Paperlogy 폰트 직접 적용
각 페이지별 개별 레이아웃 구성
Flexbox 기반 정렬, 공간 배치
